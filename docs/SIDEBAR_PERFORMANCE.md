# 侧边栏验证记录（0.1.13）

前面的资源数字记录的是增加透明小猫静置动画之前的基线；最新小猫版本的数据见文末，不能沿用旧版静置完全停止的结论。

本机 macOS 26.5.2 / Apple Silicon；2026-09-21。合成七账号缓存数据，不读取凭据、不请求在线额度、不保存用户设置。资源采样与 Instruments 分开运行。

## 资源采样

| 场景 | 平均 CPU（单核百分比） | 最高 footprint MiB | 空闲唤醒/秒 |
|---|---:|---:|---:|
| 静置收起 | 0.0009% | 26.02 | 0.00 |
| 连续切换 | 0.3959% | 26.75 | 0.35 |
| 切换后静置 | 0.0003% | 24.33 | 0.00 |

120 次账号切换：主线程处理 p95 3.57 ms，最大 5.86 ms。这里测量的是事件处理，不是逐帧呈现时间。单次短采样不证明长期零耗电或无内存泄漏；真实账号网络刷新仍有独立开销。

## 交互与视觉

34 项单元测试、28 项侧栏交互断言、59 项原有 UI 回归检查通过。覆盖自由位置、贴边、闲置胶囊、快速反向收放、固定详情、临时隐藏恢复、模拟休眠、单账号和无账号、模式切换。检查了条带、详情、悬浮胶囊和贴边把手渲染图。

动画采用原生图层一次性插值，渐变为静态，不使用循环呼吸、实时模糊或常驻逐帧计时器。停留只更新已有内容，悬停不触发网络查询。

## 复现

```sh
python3 scripts/test-sidebar.py --output build/sidebar-resource-check
python3 scripts/test-sidebar.py --trace --output build/sidebar-frame-check
```

不要同时构建覆盖正在测试的可执行文件，也不要并发运行两个 GUI 场景。轨迹保存可能耗时，脚本给予独立保存等待时间；不完整轨迹不能证明无卡顿。真实跨屏拖动、macOS 27 以及不同刷新率屏幕仍需分别验收。

安装版真实七账号短采样（35 秒，未主动刷新）：平均 CPU 0.0012%，最高 footprint 27.47 MiB，空闲唤醒 0.00/秒。此采样只覆盖当前缓存稳定期。

## 帧分析限制

两次 Animation Hitches 采集均在目标进程正常结束后停留于保存阶段。第二次延长等待后，xctrace 线程采样仍显示 DTXConnectionServices 信号量等待；轨迹无法完整导出。已停止本次测试自己的分析器进程。28 项交互断言通过，但逐帧结果为未完成，不能以空记录宣称零卡顿。进一步改为目标退出前结束 60 秒采集，第三次仍在保存阶段等待超过一分钟，未得到完整轨迹。测试自己的分析器进程均已停止；逐帧呈现仍需在 Instruments 环境恢复后补测。

本机 Computer Use 验证了贴边把手展开及七个真实账号的显示；自由拖动/跨屏的鼠标验收未完成，几何与快速反向收放已由原生测试覆盖。

## 详情布局回归修复

用户实际截图暴露了此前测试遗漏：详情子视图预先设置为目标高度，窗口再调整高度时 `.height` 自动伸缩再次应用差值，造成标题裁切或大面积空白。新增切换不同额度数量的 hosting frame 断言，在修改前稳定失败，修复后通过。现在先确定窗口最终几何，再从容器 bounds 布局内容与箭头；内容不再独立自动伸缩，详情仅使用可取消淡入淡出。

增加错误提示、连续不同高度切换、淡出途中重新打开及无账号 tooltip 检查，侧栏共 34 项检查通过（包括完成标记）。实际渲染检查确认四项额度、错误提示、标题和页脚完整；34 项单元测试及 59 项原有 UI smoke 也通过。修复版已通过 Developer ID 签名检查，安装后二进制与构建一致，实际展开验证七个账号显示正常。资源数据为上一次侧栏实现短采样，不作为本次布局修复后的重测数据。

## 多屏绑定修复

此前首次拖动前 screenID 为空，收放和详情定位重新读取 NSScreen.main，随主窗口焦点改变可能跳屏。现在首次显示立即保存屏幕编号，刷新/收放不重新选择屏幕；主动拖动时更新编号，断屏后选择并记住可用屏幕，重新连接不会抢回位置。没有新增鼠标监听或计时器。

36 项单元测试、40 项侧栏检查（含完成标记）和 59 项原有 UI smoke 通过。测试在本机当前两块物理屏幕上分别放置原生侧栏窗口，验证收起、展开、屏幕参数刷新及详情均在该屏幕内；断开/重新连接策略用屏幕 ID 列表单元测试覆盖，没有实际拔插显示器。动画重新打开检查改为有界等待应用自己的淡入淡出完成，不再把任意 AppKit 图层动画算作残留关闭动画。

## 透明小猫与分阶段悬停

按后续交互要求，收起状态改为独立透明小猫，取消胶囊底色和边框；自由悬浮显示整只，贴边露出半只。滑过贴边窗口由 18 点扩至 28 点、外边缘固定；停留 0.45 秒才展开，离开取消待展开操作。静置原生图层每 6.8 秒眨眼、12 秒轻微歪头，隐藏、休眠、低电量和减少动态效果时停止。新增动画不使用应用逐帧计时器。

36 项单元测试、47 项侧栏及基准检查通过。下列为七账号脱敏缓存数据短采样，CPU 为应用进程单核百分比，不包含 WindowServer/GPU 全部耗能，不可宣称零成本或长期无泄漏。

| 场景 | 平均 CPU | 最大 footprint MiB | 空闲唤醒/秒 |
|---|---:|---:|---:|
| 小猫静置 | 0.000194% | 26.70 | 0.00 |
| 连续详情切换 | 0.136925% | 27.09 | 0.15 |
| 切换后小猫静置 | 0.000133% | 26.31 | 0.00 |

切换主线程处理时间 p95 12.58 ms，最大 15.79 ms；这不是逐帧呈现时间。

进一步排查淡入回归：可见透明度已为 1、关闭任务已取消时，渲染服务器仍可能保留已结束动画的 key。因此该检查改为验证实际呈现透明度和关闭任务，而不以 key 残留直接判定隐藏错误。

## 像素黑猫造型

按参考图重做为原生像素轮廓：黑色身体、黄色方眼、不对称尖耳、扒边爪子和卷尾巴。自由悬浮透明窗口为 40×60 点，贴边保留 18 点、滑过探出到 28 点；左边停靠镜像朝向屏幕内侧。保留原有静置、悬停阶段与节能策略，不加载 GIF/视频或新增帧计时器。

最终长身体造型：36 项单元测试、46 项侧栏检查、59 项原有 UI smoke 通过；检查了完整小猫和贴边探头渲染。短身体图稿曾运行 47 项含基准场景检查，其原始资源数据在 build/sidebar-pixel-final；不将该图稿的数字作为最终长身体造型的重测结果。

最终安装版 35 秒真实账号静置采样：平均应用 CPU 0.00770%，最高 footprint 24.11 MiB，空闲唤醒 0.00/秒。包含小猫静置动画，但不代表 WindowServer/GPU 总开销、长期耗电或逐帧呈现结果。
